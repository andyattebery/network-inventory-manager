- Plan decisions and their sources live in `plans/2026-10-20-uv-uv2nix.md` (each cites official

- User feedback during planning (2026-10-20): research idioms on the internet (official docs), do not
  copy patterns from other `~/Projects` repos — they are AI-written. The first plan draft did copy
  from `distro-iso-feed-downloader` (Dockerfile layout, CI steps, `--frozen`); all of that was
  replaced by uv's Docker / GitHub Actions guides.
- Rejected during planning, with evidence:
  - Forcing tests via an env-var reference to a test drv: my invention; replaced first by nixpkgs
    `doInstallCheck`, then dropped when the user chose a test-gated `release` branch (uv2nix's
    `passthru.tests` + `checks` pattern).

    *revisions* never make older uv error; template's `pkgs.uv` kept.
  - Moving `latest` tag for homelab: git tags are meant immutable; a branch is the nixpkgs-channel
    idiom. FlakeHub semver considered (third-party service), not chosen.
  - VCS-derived version: `uv_build` rejects dynamic metadata.
- Execution rulings (executing-plans skill vs global CLAUDE.md — CLAUDE.md wins):
  - Ruling: no worktree, no commits; edits stay uncommitted on `main` — git writes need the user's
    words and the plan leaves commit/push/tag to the user — cost if wrong: user commits in one go.
  - Ruling: this file is the ledger; the skill's `.superpowers/sdd` scripts are not used (they need a
    writing-plans brief structure this plan does not have) — cost if wrong: none, same record.
  - Ruling: TDD's "configuration files" exception applies (packaging/CI config, no app code changes);
    the plan's RED/GREEN verification steps are the gates — cost if wrong: a config path only
    verified green.
